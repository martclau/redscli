RationalEdge DataSet (REDS) APIv1

This document contains the OpenAPI specification for the RationalEdge DataSet (REDS) API v1.
Base URL

https://reds.rationaledge.io/api/v1

Authentication

All endpoints require authentication:

    API v1: Use API tokens with Authorization: Bearer <token> header

Error Responses

All API v1 error responses use a standard error envelope:

{
  "error": true,
  "code": "not_found",
  "message": "File with hash abc123... not found",
  "detail": null
}

Error Codes:
HTTP Status	Error Code	Description
400	bad_request	Invalid query syntax, unknown field, etc.
401	unauthorized	Missing or invalid API token
403	forbidden	Action not permitted (e.g., private upload without premium subscription)
404	not_found	Resource not found (also returned for inaccessible private samples to avoid leaking existence)
422	unprocessable_entity	Valid syntax but cannot process (e.g., unsupported format)
429	rate_limited	Quota exceeded
500	internal_error	Server error

GET /api/v1/search

Search Across All Collections

Search across all collections by field-based query language. Returns sample-level results for most queries. String partial-match queries (string:"value") return string metadata; use /strings/search for dedicated string browsing. String exact-match queries (string="value") return sample hashes directly.

Parameters:

    q (query, required): Search query. Please note from the example below, in case of search values with spaces or multi-term search, consider using --data-urlencode
    cursor (query, optional): Cursor for pagination, returned as next_cursor from previous response
    format (query, optional): Response format: json (default) or ndjson (streaming)
    fields (query, optional): Comma-separated list of fields to include in response

Search Operators:
Operator	Syntax	Description	Example
Partial match	field:"value"	Case-insensitive whole-word match	filetype_magika:"pebin"
Exact match	field="value"	Exact value match	filetype_magika="pebin"
Numeric >	field:>N	Greater than	filesize:>100000
Numeric <	field:<N	Less than	filesize:<1000
AND	+	Must include	filetype:"PE32" +filesize:>1000
OR	|	Either match	filetype:"PE32" |filetype:"ELF"
NOT	-	Must exclude	-is_packed=1

    Note: Mixed AND/OR operators in the same query are not supported and return 400.

Responses:

    200: Successful Response
    400: Bad Request (invalid query syntax, unknown field, mixed operators)

Response Format:

{
  "results": [
    {"_source": {"sha256": "abc...", "md5": "def...", "filetype_magika": "pebin", ...}}
  ],
  "total_count": 1234,
  "query_time_ms": 45.2,
  "has_more": true,
  "next_cursor": "abc..."
}

Special behavior for string= exact match:

When using exact match on string fields (string="exact value"), the /search endpoint returns sample hashes (same format as /strings/samples) instead of string metadata. This aligns string= with how every other field's exact match works.

# Returns sample-level results (sha256, md5, filetype, etc.)
curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  -G "https://reds.rationaledge.io/api/v1/search" \
  --data-urlencode 'q=string="GetProcAddress"'

# Returns string metadata (string, encoding, frequency, rarity)
curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  -G "https://reds.rationaledge.io/api/v1/search" \
  --data-urlencode 'q=string:"GetProcAddress"'

Examples:

curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  'https://reds.rationaledge.io/api/v1/search?q=packer="KByS"'

curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  -G "https://reds.rationaledge.io/api/v1/search" \
  --data-urlencode 'q=compiler:"Visual Basic"'

curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  -G "https://reds.rationaledge.io/api/v1/search" \
  --data-urlencode 'q=has_overlay=1 -language:"go"'

GET /api/v1/file/{hash_value}

Look Up Full Sample Details

Look up full analysis details for a sample by MD5, SHA1, or SHA256 hash. Privacy-aware: private samples are only visible to the uploader or their organization.

Parameters:

    hash_value (path, required): MD5, SHA1 or SHA256

Responses:

    200: Successful Response - sample fully analyzed
    202: Accepted - sample exists in catalog but has not been analyzed yet (see On-Demand Analysis below)
    400: Invalid hash format
    404: Sample not found or not accessible (privacy)

Both 200 and 202 responses share a consistent shape with status and available_collections fields, making it easy to branch logic:

Response Format (200 - Complete):

{
  "status": "complete",
  "available_collections": ["basic_properties", "hashes", "pe_features", "strings", ...],
  "basic_properties": [...],
  "hashes": [...],
  "pe_features": [...],
  ...
}

Response Format (202 - Catalog Only):

{
  "status": "catalog_only",
  "available_collections": [],
  "catalog_only": true,
  "sha256": "7b864591a77a15197d9f25ed3e625b50576ffc061f2849ac6fcc245d296b7357",
  "filetype_magika": "pebin",
  "file_size": 245760,
  "first_seen": "2025-12-16T00:00:00",
  "analysis_supported": true,
  "supported_formats": ["pebin", "macho", "elf", "apk"],
  "message": "Sample exists in archive but has not been analyzed yet."
}

Use the POST /api/v1/analyze-sample/{sha256} endpoint to trigger analysis for catalog-only samples.

Example:

curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  "https://reds.rationaledge.io/api/v1/file/0f5409a5df1f916fe532696746a46d92cb561d981953d9ec30712d6d4670a13f"

# Check response status
response=$(curl -s -H "Authorization: Bearer $REDS_API_TOKEN" \
  "https://reds.rationaledge.io/api/v1/file/abc123...")
echo "$response" | jq '.status'  # "complete" or "catalog_only"
echo "$response" | jq '.available_collections'  # list of collections with data

POST /api/v1/analyze-sample/{sha256}

Trigger On-Demand Analysis

Trigger analysis for a sample that exists in the catalog but has not been analyzed yet. This endpoint queues feature extraction and code analysis jobs for the sample.

Parameters:

    sha256 (path, required): SHA256 hash of the sample (64 hex characters)

Responses:

    200: Success - analysis queued or format not supported
    404: Sample not found in catalog
    401: Unauthorized
    409: Conflict - sample has already been analyzed

Response Format (Queued):

{
  "status": "queued",
  "sha256": "7b864591a77a15197d9f25ed3e625b50576ffc061f2849ac6fcc245d296b7357",
  "message": "Analysis jobs queued successfully",
  "feature_job_id": "job_2184fe9c-b40e-481d-b24a-28cd46e3625e",
  "decompile_job_id": "job_3295gf0d-c51f-592e-c35b-39de57f4736f",
  "download_available": true,
  "filetype_magika": "pebin",
  "file_size": 245760,
  "supported_formats": ["pebin", "macho", "elf", "apk"]
}

Response Format (Unsupported Format):

{
  "status": "unsupported_format",
  "sha256": "7b864591a77a15197d9f25ed3e625b50576ffc061f2849ac6fcc245d296b7357",
  "message": "File format 'pdf' is not supported for analysis",
  "download_available": true,
  "filetype_magika": "pdf",
  "file_size": 102400,
  "supported_formats": ["pebin", "macho", "elf", "apk"]
}

Response Format (Already Analyzed - 409):

{
  "detail": "Sample has already been analyzed"
}

Examples:

# Trigger analysis for a catalog-only sample
curl -X POST -H "Authorization: Bearer $REDS_API_TOKEN" \
  "https://reds.rationaledge.io/api/v1/analyze-sample/7b864591a77a15197d9f25ed3e625b50576ffc061f2849ac6fcc245d296b7357"

# Check job status after triggering analysis
curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  "https://reds.rationaledge.io/api/v1/job/job_2184fe9c-b40e-481d-b24a-28cd46e3625e"

Workflow Example (Python):

import requests

API_TOKEN = "your_api_token"
BASE_URL = "https://reds.rationaledge.io/api/v1"
SAMPLE_SHA256 = "7b864591a77a15197d9f25ed3e625b50576ffc061f2849ac6fcc245d296b7357"
headers = {"Authorization": f"Bearer {API_TOKEN}"}

# Step 1: Check if sample exists and its analysis status
response = requests.get(f"{BASE_URL}/file/{SAMPLE_SHA256}", headers=headers)

data = response.json()

if data["status"] == "complete":
    print(f"Sample fully analyzed, collections: {data['available_collections']}")
    sample_data = data
elif data["status"] == "catalog_only":
    # Sample exists but not analyzed - trigger analysis
    if data["analysis_supported"]:
        # Step 2: Trigger analysis
        analyze_response = requests.post(
            f"{BASE_URL}/analyze-sample/{SAMPLE_SHA256}",
            headers=headers
        )
        result = analyze_response.json()

        if result["status"] == "queued":
            print(f"Analysis queued: {result['feature_job_id']}")
        else:
            print(f"Cannot analyze: {result['message']}")
    else:
        print(f"Format not supported: {data['filetype_magika']}")
elif response.status_code == 404:
    print("Sample not found")

POST /api/v1/analyze-code/{sha256}

Run Code Analysis Only

Run code analysis only for a sample that has already been analyzed but is missing code-related data. This is useful when feature extraction succeeded but code analysis failed or was not run.

Parameters:

GET /api/v1/download/{hash_value}

Download Sample

Download a malware sample binary as a password-protected ZIP archive. The ZIP password is infected.

Parameters:

    hash_value (path, required): MD5, SHA1 or SHA256

Responses:

    200: Successful Response (ZIP binary stream)
    404: Sample not found or not accessible (privacy-aware)

Example:

# Download as ZIP file
curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  "https://reds.rationaledge.io/api/v1/download/0f5409a5df1f916fe532696746a46d92cb561d981953d9ec30712d6d4670a13f" -J -O

# Extract (password: infected)
unzip -P infected downloaded_file.zip

Python example:

import zipfile, io, requests

response = requests.get(
    f"{BASE_URL}/download/{sha256}",
    headers={"Authorization": f"Bearer {API_TOKEN}"}
)
with zipfile.ZipFile(io.BytesIO(response.content)) as zf:
    zf.extractall(pwd=b"infected")

Code Analysis Endpoints

The Code Analysis API provides programmatic access to decompiled and disassembled function data extracted from malware samples. These endpoints support cursor-based pagination for efficient retrieval of large function sets.
Supported Code Formats

The code analysis endpoints automatically detect the sample format and query the appropriate data source. The same endpoints serve both formats transparently:
Sample Format	Decompiled Data	Disassembled Data	Notes
PE/ELF/MACHO binaries	Decompiled functions	Disassembled functions (x86/x64/ARM assembly)	Address-based cursor pagination
APK (Android)	Decompiled methods (Java/Kotlin)	Smali methods (Dalvik bytecode)	Offset-based cursor pagination

Key differences for APK samples:

    decompiled_function_address and disassembled_function_address will be null (APK methods don't have fixed memory addresses)
    Decompiled code contains Java/Kotlin source instead of C pseudocode
    Disassembled code contains Smali bytecode instead of x86/ARM assembly

GET /api/v1/code/search

Search for Code Functions

Dedicated endpoint for searching decompiled and disassembled functions across the dataset. Only accepts code-domain fields. The endpoint automatically routes to the correct data source (Binary Ninja or APK) based on the field used.

Supported fields:
Field	Description	Data Source
decompiled_function	Search decompiled function content	PE/ELF/MACHO
decompiled_function_name	Search by function name	PE/ELF/MACHO
decompiled_function_hash	Exact match on function hash	PE/ELF/MACHO
disassembled_function	Search disassembled function content	PE/ELF/MACHO
disassembled_function_hash	Exact match on disassembled hash	PE/ELF/MACHO
decompiled_method_hash	Exact match on decompiled method hash	APK
smali_method_hash	Exact match on smali method hash	APK

Parameters:

    q (query, required): Code-domain search query (e.g., decompiled_function:"CreateFile")
    cursor (query, optional): Cursor for pagination, returned as next_cursor from previous response

Responses:

    200: Successful Response
    400: Bad Request (non-code-domain fields rejected)
    401: Unauthorized

Response Format:

{
  "results": [
    {
      "_source": {
        "decompiled_function_hash": "a1b2c3d4e5f6...",
        "decompiled_function": "HANDLE CreateFileW(...) {\n    ...\n}",
        "sha256": ["abc123...", "def456..."],
        "decompiled_function_name": ["CreateFileW", "CreateFileW"],
        "decompiled_function_address": [4194304, 4194304],
        "decompiled_function_prototype": ["HANDLE CreateFileW(...)", "HANDLE CreateFileW(...)"],
        "visibility_scope": ["public", "public"]
      }
    }
  ],
  "total_count": 15,
  "query_time_ms": 62.8,
  "has_more": true,
  "next_cursor": "abc..."
}

Important Notes:

    Scalar vs array fields: decompiled_function_hash and decompiled_function (the code content) are scalars — they identify the unique function. All other fields (sha256, decompiled_function_name, decompiled_function_address, decompiled_function_prototype, visibility_scope, yara_rules, malcontent_risk_level, malcontent_risk_score) are arrays with one entry per sample sharing that function.
    Sharing count: There is no dedicated sharing_count field. Use len(sha256) to get the number of samples sharing a function.
    sha256 is always a list: In code search results, sha256 is always an array of sample hashes that contain the function. This is different from general /search where sha256 is always a string.

Examples:

# Search for decompiled functions by name
curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  -G "https://reds.rationaledge.io/api/v1/code/search" \
  --data-urlencode 'q=decompiled_function:"CreateFile"'

# Search by function hash
curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  -G "https://reds.rationaledge.io/api/v1/code/search" \
  --data-urlencode 'q=decompiled_function_hash="a1b2c3d4e5f6"'

# Search disassembled functions
curl -H "Authorization: Bearer $REDS_API_TOKEN" \
  -G "https://reds.rationaledge.io/api/v1/code/search" \

Code Analysis - Pagination Guide

The code analysis endpoints use cursor-based pagination for efficient traversal of large function sets.
How Cursor Pagination Works

    First Request: Call the endpoint without a cursor (or with cursor=0)
    Check Response: Look at pagination.has_more to see if more data exists
    Next Page: Use pagination.next_cursor as the cursor parameter for the next request
    Repeat: Continue until has_more is false

Example Pagination Loop (Python)

import requests

API_TOKEN = "your_api_token"
BASE_URL = "https://reds.rationaledge.io/api/v1"
SAMPLE_SHA256 = "0f5409a5df1f916fe532696746a46d92cb561d981953d9ec30712d6d4670a13f"

headers = {"Authorization": f"Bearer {API_TOKEN}"}
all_functions = []
cursor = 0

while True:
    response = requests.get(
        f"{BASE_URL}/samples/{SAMPLE_SHA256}/functions/decompiled",
        headers=headers,
        params={"cursor": cursor, "limit": 100}
    )
    response.raise_for_status()
    data = response.json()

    all_functions.extend(data["data"])

    if not data["pagination"]["has_more"]:
        break

    cursor = data["pagination"]["next_cursor"]

print(f"Retrieved {len(all_functions)} decompiled functions")

Strings Search

The Strings Search API provides programmatic access to search and analyze strings extracted from malware samples across the dataset. This is integrated with the main search endpoint and includes a dedicated endpoint for retrieving samples that share specific strings.
Understanding Parameter Formats

The API uses two different parameter formats depending on the endpoint type:
Endpoint Type	Parameter	Format	Example
Query syntax (/search)	q	Quotes required for string values	q=string:"GetProcAddress"
Direct lookup (/strings/samples)	string	Raw value, no quotes	string=GetProcAddress

Why the difference?

    The /search endpoint uses a query language where quotes delimit values (like Elasticsearch or GitHub search)
    The /strings/samples endpoint uses dedicated parameters where URL encoding handles special characters

GET /api/v1/strings/search

Search for Strings by Partial Match

Dedicated endpoint for browsing strings across the dataset. Only accepts string-domain fields (string, string_encoding, string_length, string_entropy). Returns string metadata with linkage fields for pivoting to /strings/samples.

Use this endpoint for string browsing and discovery. For finding samples that contain a known exact string, use /strings/samples directly or /search?q=string="exact value".

Parameters:

GET /api/v1/samples/{sha256}/strings

Get Paginated Strings List

Retrieve a paginated list of strings extracted from a malware sample with optional filtering. Each string includes sharing statistics.

Parameters:

    sha256 (path, required): SHA256 hash of the sample (64 hex characters)
    cursor (query, optional): Cursor for pagination, returned as next_cursor from previous response
    limit (query, optional): Number of strings to return, range: 1-1000, default: 500
    search (query, optional): Search term to filter strings
    encoding (query, optional): Filter by encoding type (e.g., AsciiString, Utf16String)
    min_entropy (query, optional): Minimum entropy filter (0.0-8.0)
    max_entropy (query, optional): Maximum entropy filter (0.0-8.0)

Responses:

    200: Successful Response
    400: Bad Request (Invalid SHA256 format, cursor, or filter values)
    404: Sample not found
    401: Unauthorized
    429: Quota exceeded

Response Format:

{
  "data": [
    {
      "string": "GetProcAddress",
      "string_raw": "476574P726f634164647265737300",
      "string_encoding": "AsciiString",
      "string_offset": 12456,
      "string_length": 14,
      "string_raw_length": 15,
      "string_entropy": 3.52,
      "frequency": 15420,
      "rarity_class": "library"
    }
  ],
  "pagination": {
    "total": 1523,
    "has_more": true,
    "next_cursor": "500"
  },
  "query_time_ms": 89.4
}

String Info Fields:
Field	Type	Description
string	String	Decoded string content
string_raw	String	Raw bytes as hex string
string_encoding	String	Detected encoding (AsciiString, Utf16String, etc.)
string_offset	Integer	File offset where string was found
string_length	Integer	Length of decoded string

string_entropy	Float	Shannon entropy (0.0-8.0)

Use cursor-based pagination to retrieve all strings. When has_more is true, pass the next_cursor value as the cursor parameter in your next request.

Example: Complete Strings Analysis Workflow (Python)

import requests

API_TOKEN = "your_api_token"
BASE_URL = "https://reds.rationaledge.io/api/v1"
SAMPLE_SHA256 = "0f5409a5df1f916fe532696746a46d92cb561d981953d9ec30712d6d4670a13f"
headers = {"Authorization": f"Bearer {API_TOKEN}"}

# Step 1: Get aggregate statistics
stats_response = requests.get(
    f"{BASE_URL}/samples/{SAMPLE_SHA256}/strings/statistics",
    headers=headers
)
stats = stats_response.json()

# Check if sample has strings data
if stats.get("total_strings", 0) == 0:
    print("Sample has no strings data")
    exit()

print(f"Sample: {stats['sample_sha256']}")
print(f"Total strings: {stats['total_strings']}")
print(f"Unique strings: {stats['unique_strings']} ({stats['unique_strings']/stats['total_strings']*100:.1f}%)")
print(f"Shared strings: {stats['shared_strings']}")
print(f"\nRarity distribution:")
for tier, count in stats['rarity_distribution'].items():
    print(f"  {tier}: {count}")

# Step 2: Get high-entropy strings (potentially obfuscated)
high_entropy_response = requests.get(
    f"{BASE_URL}/samples/{SAMPLE_SHA256}/strings",
    headers=headers,
    params={"min_entropy": 4.5, "limit": 50}
)
high_entropy_strings = high_entropy_response.json()

print(f"\nHigh-entropy strings (entropy > 4.5):")
for s in high_entropy_strings["data"][:5]:
    print(f"  [{s['string_entropy']:.2f}] {s['string'][:60]}...")

# Step 3: Find rare strings (potential IOCs) using cursor pagination
rare_strings = []
cursor = None
while True:
    params = {"limit": 500}
    if cursor:
        params["cursor"] = cursor

    response = requests.get(
        f"{BASE_URL}/samples/{SAMPLE_SHA256}/strings",
        headers=headers,
        params=params
    )
    data = response.json()

    for s in data["data"]:
        if s["rarity_class"] in ["unique", "rare"]:
            rare_strings.append(s)

    if not data["pagination"]["has_more"]:
        break
    cursor = data["pagination"]["next_cursor"]

print(f"\nFound {len(rare_strings)} rare/unique strings (potential IOCs)")
for s in rare_strings[:10]:
    print(f"  [{s['rarity_class']}] {s['string'][:60]}...")

    # Get samples sharing this rare string
    if s["frequency"] > 1:
        samples_response = requests.get(
            f"{BASE_URL}/strings/samples",
            headers=headers,
            params={"string": s["string"], "limit": 5}
        )
        samples = samples_response.json()
        print(f"    Shared with {samples['pagination']['total']} samples:")
        for sample in samples["data"]:
            print(f"      - {sample['sha256'][:16]}...")

import requests

API_TOKEN = "your_api_token"
BASE_URL = "https://reds.rationaledge.io/api/v1"
SAMPLE_SHA256 = "0f5409a5df1f916fe532696746a46d92cb561d981953d9ec30712d6d4670a13f"
headers = {"Authorization": f"Bearer {API_TOKEN}"}

# Step 1: Check if sample has IOCs
summary_response = requests.get(
    f"{BASE_URL}/samples/{SAMPLE_SHA256}/iocs/summary",
    headers=headers
)
summary = summary_response.json()

if not summary["has_iocs"]:
    print("Sample has no extracted IOCs")
    exit()

print(f"Sample: {summary['sha256']}")
print(f"Total IOCs: {summary['total_count']}")
print(f"\nIOC distribution:")
for ioc_type, count in summary["type_counts"].items():
    print(f"  {ioc_type}: {count}")

# Step 2: Get full IOC details
iocs_response = requests.get(
    f"{BASE_URL}/samples/{SAMPLE_SHA256}/iocs",
    headers=headers
)
iocs = iocs_response.json()

print(f"\n--- Detailed IOCs ---")
for group in iocs["groups"]:
    print(f"\n{group['ioc_type']} ({group['total_count']}):")
    for ioc in group["iocs"]:
        sources = ", ".join([s["source_type"] for s in ioc["sources"]])
        print(f"  - {ioc['ioc_value']}")
        print(f"    Sources: {sources}")
        print(f"    Shared by: {ioc['count']} samples")

# Step 3: Find other samples with the same IOC
for group in iocs["groups"]:
    if group["ioc_type"] in ["ipv4", "url", "fqdn"]:
        for ioc in group["iocs"]:
            if ioc["count"] > 1:
                # Search for other samples with this IOC
                search_response = requests.get(
                    f"{BASE_URL}/search",
                    headers=headers,
                    params={"q": f'{group["ioc_type"]}="{ioc["ioc_value"]}"'}
                )
                results = search_response.json()

                print(f"\nSamples sharing {group['ioc_type']}={ioc['ioc_value']}:")
                for result in results.get("results", [])[:5]:
                    sha256 = result["_source"].get("sha256_hashes", ["N/A"])[0]
                    print(f"  - {sha256[:16]}...")

POST /api/v1/bulk-search

Bulk Search: Multiple Values of One Field

Search for multiple exact values of a single field in one request. For example, check whether a list of SHA256 hashes exists in REDS, or look up multiple IPv4 indicators at once.

Costs 1 credit per request, regardless of the number of values. Maximum 300 values per request.

Request Body (JSON):
Field	Type	Required	Description
field	string	yes	The field to search (must be a bulk-eligible field, see /bulk-search/fields)
values	array of strings	yes	Values to search for (one per entry, exact match). Max 300.
cursor	string	no	Pagination cursor from previous response's next_cursor

Responses:

    200: Successful Response
    400: Bad Request (invalid field, validation error)
    429: Quota exceeded

Response Format:

{
  "results": [
    {"sha256": "abc...", "md5": "def...", "filetype_magika": "pebin", ...}
  ],
  "total_count": 8,
  "query_time_ms": 120,
  "has_more": false,
  "next_cursor": null,
  "determined_collection": "basic_properties",
  "bulk_search_meta": {
    "field": "sha256",
    "total_queried": 10,
    "total_matched": 8,
    "total_unmatched": 2,
    "unmatched_values": [
      "aaaa...missing_hash_1...",
      "bbbb...missing_hash_2..."
    ]
  }
}

The bulk_search_meta object tells you exactly which of your input values were found and which were not, so you can immediately identify indicators missing from the dataset.

Examples:

# Search for multiple SHA256 hashes

    "field": "sha256",
